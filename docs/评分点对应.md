# 官方评分点 ↔ 本作品设计对照

> 用途：成果页文案取材、答辩 Q&A 准备、自查哪些分数还没拿到。
> 评分标准来源：《第一届校园 AI 智能体创新应用大赛实施方案》第三节（五），满分 100。
> 赛道：AI+教学科研 · 计算机大类。作品：CS 科研工坊（cs-research-studio）。

---

## 一、需求价值 30 分

**官方要点**：选题是否聚焦真实痛点；问题是否具有理论深度与实际应用价值；场景适配性与推广潜力。

### 我们的痛点叙事（答辩开场用）

开题阶段的四个真实卡点，每个都能被具体化成一个场景：

| 卡点 | 学生实际处境 | 我们的对应能力 |
|---|---|---|
| 文献找不到 | 只会用关键词硬搜，不知道检索式怎么构造，漏掉经典工作 | 检索策略模板 + arXiv 批量检索下载 + 检索记录表 |
| 论文读不懂 | 英文长句啃不动，读完不知道方法细节与局限在哪 | 术语对齐翻译 + 五要素精读卡 + 可信度标注 |
| 环境配不起来 | 复现论文被 CUDA/依赖版本卡死，一周配不通 | Linux 环境自检脚本 + 版本矩阵核对 + 环境说明报告 |
| 写作不规范 | 综述写成文献堆砌，引用格式混乱 | IMRaD 结构 + 引用规范检查 + 强断言配证据 |

### 得分要点与待补证据

- ✅ 选题命中赛道一参考命题原文："科研文献助手：输入研究方向，自动检索、摘要并生成文献综述框架"
- ⚠️ **推广潜力**目前无证据支撑 —— 需要：至少 3 个不同方向（如 AI / 软件工程 / 物联网）的真实跑通案例 → `docs/cases/`
- ⚠️ **真实用户验证**缺失 —— 需要：找 3-5 名同学试用并留反馈截图，这是 30 分里最容易补的一块

## 二、创新创意 25 分

**官方要点**：解决方案是否有创新点、是否提出新颖方法；设计方案具备理论基础与可实现路径。

### 三个可讲的创新点（按说服力排序）

**1. 人在回路确认制 —— 主动划定 AI 边界**

不是"AI 代做科研"，而是"AI 做苦力、人类做判断"。三个关键节点强制暂停等待用户拍板：研究空白清单后、实验方案后、终稿交付前。每个成员都有明确的"AI 做 / 用户做"边界表。

> 评委隐含关切（协办单位含教务处、学生工作部）：学术诚信。这个设计把"防止 AI 代做"从外部约束变成了系统内建机制，是主动得分点，不要当作限制来讲。

**2. 三道质量门 —— 每道工序有可验证的通过条件**

| 门 | 检查什么 | 不通过的后果 |
|---|---|---|
| 引用真实门 | 所有引用必须有作者、年份、出处；无法核实的标"待核实" | 打回文献调研重做 |
| 可执行门 | 实验方案必须有假设、可获取数据、可运行路径 | 打回实验设计重做 |
| 规范门 | 术语一致、图表自解释、引用格式统一、无口语化 | 打回写作重做 |

**3. 可信度标注机制 —— 防止推断被当结论传播**

文献解读的每条结论必须标注 `[原文结论]` / `[原文主张-弱证据]` / `[解读者推断]`，下游环节引用时保留标注。这是对"AI 幻觉"的具体工程化应对，不是口号。

### 待补证据

- ⚠️ 需要一段**质量门拦截实录**：故意喂一个幻觉引用，演示它被拦下并打回的过程。这比任何 PPT 都更有说服力，务必录进演示视频（S1 阶段即可录制）

## 三、技术实现 25 分

**官方要点**：WorkBuddy 平台功能应用是否合理（**知识库、工作流、多 Agent 等**）；Agent 链接真实有效；交互体验流畅。

**这是官方点名的三项，我们全部命中 —— 必须让评委"看见"，不能只展示最终结果。**

| 官方点名能力 | 我们的实现 | 演示时要展示的画面 |
|---|---|---|
| **多 Agent** | Team 型专家团：科研总规划 + 文献调研专家 + 实验设计专家 + 学术写作专家 | 任务下发后，主理人依次调度各角色、角色回传产出的过程 |
| **工作流** | 7 条路由：全流程开题 A、三项专项直调 B/C/D、文献获取解读 E、环境配置 F、知识直答 G | 输入一个问题，展示它被路由到正确工作流 |
| **知识库** | `cs-knowledge-base`：计算机科学 / 软件工程 / 物联网 / 人工智能四份领域图谱 | 展示知识库文件结构 + 一次知识查询的问答 |

### 加分项：技能是可执行的，不是提示词堆叠

| 技能 | 真实可执行的证据 |
|---|---|
| literature-retrieval | `arxiv_fetch.py`：stdio-only 脚本，实际调用 arXiv API 下载 PDF |
| linux-env-setup | `env-check.sh`：在真机上跑出 GPU/CUDA/框架/网络现状 |
| paper-reading / cs-knowledge-base | 结构化模板与术语对照表，产出可核验 |

### 待补证据

- ⚠️ **可访问的智能体链接**：成果页必须放，且无痕窗口能打开（材料硬性要求）
- ⚠️ 交互流畅度：演示前跑 3 次完整流程，掐表看端到端耗时，超时需简化路由

## 四、完成度 20 分

**官方要点**：作品提交材料完整；答辩逻辑清晰，能准确回答评委问题（答辩针对决赛）。

### 材料清单

- [ ] 可访问成果页（团队介绍 / SOP 图解 / 演示视频 / 真实案例输出物）
- [ ] 智能体链接（无痕窗口可打开）
- [ ] 3 分钟以内操作录屏
- [ ] 说明文档：SOP、角色分工、技术方案
- [ ] **《作品提交规范》附件要求的其他材料** —— 该附件未随实施方案下发，需向赛区索取

### 答辩（5 分钟展示 + 5 分钟答辩）预案

**5 分钟展示建议配比：**

| 时间 | 内容 |
|---|---|
| 0:00-0:45 | 痛点：四个卡点，用真实场景讲（或直接用一段同学访谈） |
| 0:45-1:45 | 方案：多 Agent 分工图 + 三道质量门 |
| 1:45-3:30 | 演示：现场跑一个真实选题，走到文献下载与环境配置（**展示过程，不是结果**） |
| 3:30-4:15 | 人在回路：为什么 AI 不代做科研，如何防学术不端 |
| 4:15-5:00 | 成果与展望：案例数据、推广场景 |

**评委大概率追问的五个问题：**

1. *"这不就是把一句话拆给三个模型吗？"* → 答：成员间不直接通信，全部经主理人中转，每步多一次核对；且每道工序有可验证的通过条件（质量门），不是拼接
2. *"引用会不会是编的？"* → 答：引用真实门 + 现场演示幻觉引用被拦下
3. *"环境配置不就是个命令清单吗？"* → 答：env-check.sh 是真跑的自检脚本，输出驱动后续差距分析，不是静态清单
4. *"学生会不会直接拿它代写论文？"* → 答：这正是我们主动限制的：三节点确认制 + 写作成员明确标注 AI 文字未经本人确认不得作为本人成果提交
5. *"换一个方向（比如物联网）还能用吗？"* → 答：知识库覆盖四大领域，案例库需跑到 3 个方向 —— **这个问题必须在 S2 前准备好真实案例**
