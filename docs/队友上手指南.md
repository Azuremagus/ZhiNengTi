# 队友上手指南

> 目标：让每个队友在自己的 WorkBuddy 里都能召唤 **cs-research-studio（CS 科研工坊）** 专家团。
> 最后更新：2026-10-21 · 对应专家包版本 v1.1.0

---

## 〇、先搞清楚一件事

WorkBuddy 的"智能体"**不是云端应用**，而是一个本地文件夹（专家包）。它没有账号体系内的自动同步，**谁要用，谁就得在自己电脑上放一份**。

所以"让团队用上"= 把这份文件夹复制到每个人的专家目录里，再执行注册。

### 开工前的两个前置条件

1. **装了 WorkBuddy**（这是废话，但要求不能太老——Team 型专家需要 `settings.json`，太旧的版本不认，装完看不到时优先怀疑这个）
2. **本机有 Python 3.10+**（只在你要用「文献检索下载」技能时才需要，装专家包本身不需要）。命令行跑 `python --version` 确认。文献检索脚本是纯标准库实现，**不需要 pip install 任何东西**

## 一、两条路，按你的角色选

| | 路径 A：只用，不改 | 路径 B：参与开发 |
|---|---|---|
| **适合谁** | 只想用它做调研/写作的队友 | 要改角色提示词、加技能的队友 |
| **拿什么** | 共享盘的 `cs-research-studio-v1.1.0.zip` | GitHub 仓库 `Azuremagus/ZhiNengTi` |
| **要不要装 Git** | 不需要 | 需要 |
| **几分钟** | 3 分钟 | 10 分钟 |
| **能改代码吗** | 不能（改了会被下次同步覆盖） | 能，且是唯一正确方式 |

> **两条路不要混用。** 走了 A 又想改代码，请删掉本地专家目录里的副本，重新走 B。

## 二、路径 A：只想用（3 分钟）

### 1. 下载并解压

从项目共享盘根目录下载 `cs-research-studio-v1.1.0.zip`（326 KB），解压到**任意一个你记得住的位置**，例如：

```
D:\my-experts\cs-research-studio\
```

解压后顶层必须是 `cs-research-studio\` 这一层目录，里面有 `agents/`、`skills/`、`settings.json`。

### 2. 复制到专家目录

打开资源管理器，地址栏粘贴并回车：

```
%USERPROFILE%\.workbuddy\plugins\marketplaces\my-experts\plugins
```

把解压出来的整个 `cs-research-studio` 文件夹复制进去。最终结构应为：

```
...\my-experts\plugins\cs-research-studio\
                        ├── .codebuddy-plugin\plugin.json
                        ├── agents\
                        ├── skills\
                        └── settings.json
```

### 3. 注册

在 WorkBuddy 对话框里直接说：

```
帮我注册并校验这个专家包：
C:\Users\<你的用户名>\.workbuddy\plugins\marketplaces\my-experts\plugins\cs-research-studio
```

它会自动跑 validate + register。看到校验通过即可。

### 4. 重启并用

**完全退出 WorkBuddy 再重新打开**（不是最小化），左侧「专家」里就能看到 **CS 科研工坊**。

### 5. 验收：怎么确认自己装成功了

逐项打勾，四项全绿才算装好：

- [ ] 左侧「专家」里能看到 **CS 科研工坊**，且类型显示为「**专家团**」（不是"专家"——显示"专家"说明装的是残包）
- [ ] 点进去能看到 **4 个角色**：科研总规划、文献调研专家、实验设计专家、学术写作专家
- [ ] 发一句 `帮我调研一下 RAG 检索增强生成在代码生成方向的研究现状`，它会先派「文献调研专家」出去，并在关键节点**停下来等你确认**（这是"人在回路"设计，不是卡壳）
- [ ] 发一句 `计算机科学和物联网的知识图谱里有哪些方向`，能答出内置知识库的内容

> 装完看不到 → 90% 是没重启。完全退出进程重开，不是关窗口最小化。

## 三、路径 B：参与开发（10 分钟）

### 1. 一次性的环境准备

需要：Git、Python 3.10+、WorkBuddy。

```bash
git clone https://github.com/Azuremagus/ZhiNengTi.git
cd ZhiNengTi
scripts\check-env.cmd          # 自检六项：git/python/专家目录/同步状态/仓库根/remote
```

> 私有仓库，拉不下来说明你还没被加为 collaborator，找队长在 GitHub 后台加。

### 2. 每次开工的流程（五步，缺一步就会"改了没生效"）

```bash
git pull                                        # 1 先同步，别基于旧版本改
# 2 只改自己认领的文件（见 README 第四节归属表）
scripts\sync-expert.cmd cs-research-studio      # 3 镜像到专家目录
python scripts\expert-manager\validate_expert.py "%USERPROFILE%\.workbuddy\plugins\marketplaces\my-experts\plugins\cs-research-studio"   # 4 校验
python scripts\expert-manager\register_expert.py "%USERPROFILE%\.workbuddy\plugins\marketplaces\my-experts\plugins\cs-research-studio"   # 5 注册
git add -A && git commit -m "feat: xxx" && git push    # 6 提交
```

### 3. 三条铁律

1. **永远改仓库里的文件，不要直接改专家目录里的副本** —— 那是部署镜像，下次同步会被静默覆盖。
2. **不要改锁定字段**（目录名、`name`、`agentName`、`agents/` 下 MD 文件名）。改了等于重建专家包，全队返工。
3. **`plugin.json` 只有队长能改**，其他人走提需求。

## 四、常见坑

| 现象 | 原因 | 解法 |
|---|---|---|
| 专家中心看不到 | 没注册，或没重启 | 跑 register + **完全退出重开** WorkBuddy |
| 打包报 "Team type must have settings.json" | 镜像目录缺 `settings.json` | 从仓库 `cs-research-studio/settings.json` 手动复制过去 |
| `env-check.sh` 在 Linux 报 `bad interpreter` | Windows 检出时换行符被转成 CRLF | 仓库已配 `.gitattributes`（`*.sh text eol=lf`）；若仍出错执行 `sed -i 's/\r$//' env-check.sh` |
| 改了文件但没生效 | 只改了仓库没同步，或只改了镜像没改仓库 | 走完上面五步 |
| `git push` 报 502 / 超时 | 本机代理干扰 | `git -c http.proxy= -c https.proxy= push origin master` |

## 五、这个专家团能干什么

四个角色，由「科研总规划」统一调度，成员之间不直连：

| 角色 | 你能问它什么 |
|---|---|
| 科研总规划 | "帮我从零开题：XXX 方向" —— 全流程调度 |
| 文献调研专家 | 检索文献、下载 arXiv PDF、翻译解读、方法对比矩阵、找研究空白 |
| 实验设计专家 | 实验方案、指标与基线、代码骨架、Linux 环境配置命令 |
| 学术写作专家 | 论文结构、章节撰写、学术润色、引用格式检查 |

内置四个技能：文献检索下载、文献翻译解读、Linux 环境配置、计算机四领域知识库（计科/软工/物联网/人工智能）。

**注意「人在回路」设计**：它会在三个节点停下来等你拍板——研究空白清单出来后、实验方案出来后、终稿交付前。这是刻意的，不是卡壳。

---

## 六、拿到了新版怎么办

如果队长更新了专家包：

- **路径 A 的人**：重新下载共享盘的 zip，覆盖本地专家目录的 `cs-research-studio` 文件夹，再跑一次注册。
- **路径 B 的人**：`git pull` → `sync-expert.cmd` → 注册。

> 反过来，如果你改了仓库内容并 push 了，**提醒队长重新打包并覆盖上传共享盘的 zip**，否则路径 A 的队友拿到的还是旧版。
