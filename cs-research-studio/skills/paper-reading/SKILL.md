# 文献翻译与解读

把一篇英文论文变成"能直接用于科研决策的中文材料"：术语准确的翻译、结构化的解读、明确标注的可信度。

## 何时使用

- 拿到一篇 PDF，需要快速判断值不值得精读（三分钟解读）
- 确定精读后，需要逐节翻译与拆解（深度解读）
- 团队成员对某篇论文的理解有分歧，需要一份中立的结构化解读作为讨论底稿

## 使用边界（人在回路）

- AI 负责：初译、术语对齐、结构化拆解、疑点标注
- **人类必须决策**：论文结论是否可信的最终判断；是否将其作为自己工作的基线；翻译稿用于投稿或正式材料时必须人工校对（AI 译文不得直接作为正式译文交付）

## 两级解读模式

### 模式一：三分钟判读（决定读不读）

只读 标题 → 摘要 → 图1/表1 → 结论第一段，输出：

```
一句话定位：这篇论文做了什么（≤50字）
与我课题的关系：直接相关 / 方法可借鉴 / 背景知识 / 无关
建议动作：精读 / 泛读 / 弃读（附理由）
```

### 模式二：深度解读（五要素卡片）

使用 `templates/five-element-card.md`，逐节翻译关键点并拆解：

1. **问题**：解决什么问题，为什么重要，与前人工作的差异
2. **方法**：核心机制（伪代码级），关键设计选择及其动机
3. **数据**：用了什么数据集/基准，规模与划分
4. **结果**：主指标数字、与基线差距、统计显著性
5. **局限**：作者自述局限 + 解读者发现的隐含假设

## 翻译规范

- 术语优先使用 `templates/translation-glossary.md` 中的对照；新术语按"英文原名（建议中译）"格式首次出现
- **不翻译的内容**：公式、代码、数据集名称、模型名称、指标缩写
- 长句拆解：英文论文的嵌套从句译成中文时拆成 2-3 个短句，不改变逻辑连接词
- 拿不准的译法标注 `[译法待确认]`，不得自行生造术语

## 解读可信度标注

每条从论文中提取的结论，标注证据类型：

| 标注 | 含义 |
|---|---|
| `[原文结论]` | 论文明确陈述，有实验支撑 |
| `[原文主张-弱证据]` | 论文声称但实验支撑不足（如只有单数据集、无消融） |
| `[解读者推断]` | AI/读者从文中推断，非原文明确陈述 |

下游环节（实验设计、写作）引用时**必须保留标注**，不允许把推断当结论传播。

## 与检索环节的衔接

输入来自 `literature-retrieval` 的产出（PDF + 检索记录表）。解读完成后，在检索记录表的对应行回填"解读结论"（精读卡片链接），保证每篇文献状态可追溯。
